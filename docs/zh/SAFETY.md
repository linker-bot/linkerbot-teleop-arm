# 运行时与标定行为

[English](../SAFETY.md)

## 接口配置

启动进程前，应配置 bitrate 并启用 CAN 接口。库只打开该接口，不运行 `sudo`、`ip` 或 `chmod`，也不修改其他接口。bitrate 参数必须为正，但不会应用到操作系统。CLI 和 ROS 节点都会在打开硬件前验证参数。

工厂在 Linux 上打开经典 SocketCAN。其他平台可以通过注入传输对象运行协议和 Session 代码，但没有原生 SocketCAN 后端。

## 帧与缓存状态

驱动拒绝超过 8 字节的经典 CAN 发送载荷和无效的标准 ID。接收时，SocketCAN 过滤 RTR/错误帧，并将原生经典帧长度限制在 8 字节以内。解码器检查处理后的 ID、标志和响应长度，无法再检测已经被归一化修改的原始 DLC。接受的 6、7、8 字节响应见 [PROTOCOL.md](PROTOCOL.md)。

只有完整的四块响应才会成为快照。新读取失败时抛出异常，缓存读取则可能在响应超时后仍返回较早的有效快照。除 `valid` 外，还应检查年龄和故障有效性；缺少故障位表示未知。Session 关闭/故障、generation 改变和检测到接收队列溢出都会使已提交数据失效。标准 ROS 话题使用弧度，兼容话题保留度数。

## 仅显式标定

启动参数 `calibration` 必须为零。CLI 和构造函数都不发送归零命令。`resetZero(joint)` 是显式库操作：索引 `0..13` 通过 `0xC0` 发送一个索引字节，`255` 则发送空载荷的 `0xC1`。发送尝试前会使缓存快照失效。库调用方可以反复调用这个操作，核心 API 没有一次性限制。

ROS 的 `~/calibrate_once` 服务默认禁用，只有启动配置设置 `allow_calibration=true` 后才允许调用。首次允许的请求会在命令排队前消耗节点内的一次性机会。worker 只尝试一次 `calibration_joint`，失败、发送结果不确定或恢复都不会触发再次尝试。重启会重置这项限制，但仍需要新的显式服务请求。限制只保存在内存中，不是持久化确认记录或幂等键。

标定完成响应尚未实现。即使 ROS 服务接受了请求，也会返回 `success=false`，因为排队或发送都不能确认设备执行完成。应读取消息和诊断了解该次尝试的状态，再通过操作人员认可的设备检查确认不确定的发送结果，之后才决定是否重发。

## 生命周期与硬件限制

缓存状态和版本访问有同步保护，打印在状态锁外使用复制的快照。应用应在销毁核心 arm 对象前结束对它的成员函数调用。借用方只关闭自己的接收队列并取消自己的 endpoint；只有约定的所有者才关闭或恢复共享 Session。已经进入驱动的调用可能使取消、恢复和退出超过请求的截止时间。完整所有权约定见 [SESSION.md](SESSION.md)。

FakeTransport、接管的数据报套接字和 Linux vcan 在不驱动硬件运动的情况下测试软件行为。物理 CAN ACK、终端电阻、bus-off、固件时序和标定完成需要设备测试。采集这些结果可参考 [SOAK.md](SOAK.md) 与 [BENCHMARK.md](BENCHMARK.md)；短生命周期测试不能证明八小时稳定性。
