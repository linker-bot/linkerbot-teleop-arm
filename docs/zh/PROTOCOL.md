# 遥操臂协议与快照契约

[English](../PROTOCOL.md)

驱动按下述规则接收帧并组装快照。面向实机发布前，还需要通过设备抓帧确认版本格式、不同固件的帧格式、标定确认机制和最大轮询频率。

## 总线帧

`ArmProtocol.h` 使用 C++17，不依赖 Linux 或 ROS 头文件。解码器接受最多带 8 字节载荷的经典 CAN 标准数据帧。`Protocol::Frame::can_id` 只保存仲裁 ID；超过 `0x7ff` 的 ID，以及带有 `is_extended`、`is_remote`、`is_error` 或 `is_fd` 标志的帧都会被拒绝。直接传入包含标志位的原始 SocketCAN ID 也会被拒绝。

SocketCAN 在帧进入 Session 前过滤 RTR 和错误帧。遥操臂从路由后的消息中复制其余的扩展帧和 FD 标志。后端会把原生经典帧的接收长度限制在 8 字节以内。独立解码器会拒绝大于 8 的 DLC，但经过这一步归一化后，原始长度异常已无法再被观察到。

## 命令

遥操臂发送以下经典 CAN 标准数据帧：

- `0x64`，空载荷：请求版本字节。
- `0x04`，空载荷：请求全部四个位置数据块。
- `0xC0`，一个取值为 `0..13` 的字节：显式重置指定关节的零点。
- `0xC1`，空载荷：显式重置所有关节的零点（`resetZero(255)`）。

`readJointState()` 使用 `0x04` 请求全部数据块。旧头文件仍保留 `0x02` 和 `0x03` 常量。驱动尚未实现标定完成 ACK。

## 响应

接受的响应如下：

- `0x64`：1 到 8 个版本字节，原样保留内容和长度。空响应无效。`getVersion()` 将第一个字节显示为十进制数字；解码器只保留字节，不规定版本格式。显示格式仍需固件确认。
- `0x65`：恰好 8 字节，对应左臂关节 0–3。
- `0x66`：左臂关节 4–6 的位置占 6 字节，可再带一个覆盖左臂全部七个关节的故障字节（DLC 为 7 或 8）。
- `0x67`：恰好 8 字节，对应右臂关节 7–10。
- `0x68`：右臂关节 11–13 的位置占 6 字节，可再带一个覆盖右臂全部七个关节的故障字节（DLC 为 7 或 8）。

每个角度使用有符号大端 16 位数，单位为 0.1 度。故障字节的位 0–6 分别描述该臂的七个关节。6 字节响应没有故障字节，因此 `fault_valid` 为 false，这些关节的故障状态为未知。

接受 8 字节的 `0x66`/`0x68` 响应，是为了兼容旧驱动的 `DLC >= 7` 行为。第 8 个字节被忽略，其含义需要固件文档说明。未知 ID 或其他归一化后的长度不会改变快照，也不会触发发布。

`decodeFrame()` 在访问载荷前检查长度，返回 `DecodeError` 和可选的解码结果。无效输入不会产生解码帧。调用方也可以直接构造 `DecodedFrame`，所以 `SnapshotAssembler` 会再次检查数据块索引、数量，以及角度是否有限且处于归一化范围内。

## 角度表示

`decodeAngle()` 使用有符号算术，避免超出范围的无符号到有符号转换，再将结果归一化到 `[-180, 180)` 度。总线上两种表示 180 度的值都会变成 -180 度。179 到 -179 的跳变会被接受，旧实现对此边界的拒绝逻辑已经移除。

`shortestAngularDelta(previous, current)` 返回同一区间内的环形角度差：179 → -179 得到 +2。它不会展开连续角度、应用关节限位、估算速度或拒绝运动；这些判断需要物理关节模型。

核心库返回度数。ROS 适配层应用方向系数，并在 `/joint_states` 上转换为弧度。旧的 `/left_arm_joint_control` 和 `/right_arm_joint_control` 话题使用相同方向系数，但保留度数；设置 `publish_legacy_topics=false` 可关闭它们。

## 完整快照

`SnapshotAssembler` 不管理线程、锁或硬件访问。运行时若在多个线程间共享它，修改和复制时都必须加锁。

四个不同的位置数据块构成一份快照，各自带有位置和单调接收时间戳。组装器只提交完整集合，`latest()` 返回其副本。第一次提交前，`valid` 为 false，填零的位置不是测量值。局部更新不会改变上一份已提交快照。

第一块到最后一块的默认到达时间差上限为 100 ms，可通过组装器构造函数修改。遥操臂使用默认值，`SessionOptions` 没有单独的时差配置。负上限会被拒绝，恰好到达上限的帧会被接受。

重复的数据块或超出时差上限的帧会使当前局部候选失效，并以该帧开始新的候选集合。倒退的时间戳和无效解码帧不会改变任何状态，包括保存的接收时钟。完整集合提交后，下一块数据开始新的候选集合。

运行时发送新请求时，`beginCycle()` 只丢弃待组装的数据，上一份完整快照仍可通过显式缓存读取获得。`beginCycle(not_before)` 还会拒绝接收时间早于请求边界的帧。连接断开或传输被替换时，`reset(generation)` 清除待组装数据和缓存有效性，包括故障有效性；它记录新的 generation，同时保留单调递增的本地快照序号。generation 和 sequence 是主机元数据，不是固件采样标识。遥操臂的新读取 API 只在查询待完成期间提交快照；仅读取缓存不会请求或组装新响应。合并请求与等待的 API 及缓存行为见 [SESSION.md](SESSION.md)。

`received_mask == 0x0f` 表示已提交的完整集合。`received_at[0..3]` 保留各块的到达时间，`captured_at` 是最后一块的到达时间，不是设备实际采集时间。`isFresh(now, max_age)` 要求快照完整且有效，并检查**全部四块**的年龄，包括最老的一块。未来时间戳或负的最大年龄无法通过检查。下一组不完整数据不会刷新旧快照的时间戳。

## 请求关联的限制

四种响应格式中没有已知的硬件周期标识。主机只允许一个在途请求，并检查接收边界、组装时间和重复数据块，但早先请求的延迟响应仍可能通过这些检查。要证明所有角度来自同一次硬件采样，需要固件序号字段或明确的传输/协议保证。

遥操臂使用 Session 的单调 `received_at`，而不是接收线程稍后处理队列帧的时间。查询既有起始边界，也有截止时间；从起始边界到实际发送之间可能发生排队或调度。完整响应超时不会让早先的缓存快照变新。

写入成功只确认本地后端接受了数据。确认标定完成需要明确的响应或读回机制，发送 `0xC0`/`0xC1` 本身不构成确认。超时、断线或进程重启后，不要重放结果不确定的命令。
