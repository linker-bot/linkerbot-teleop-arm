# 运行八小时硬件长稳测试

[English](../SOAK.md)

使用专用台架，记录适配器、固件、bitrate、终端电阻、电源、主机负载、Git 提交、内核及编译器。在进程外配置 CAN，并从该设备已经验证过的请求频率开始。配置的频率只是调度上限，不保证设备能达到相应吞吐量。

连续至少八小时记录新鲜完整快照、超时、无效帧、溢出/恢复事件、主机时间戳、进程 RSS、线程数和打开的文件描述符数。保留原始记录，将启动预热与测量阶段分开，再比较资源趋势。

在可控台架条件下注入断线/重连、缺失响应和负载，检查是否发布了无效或陈旧数据，以及是否重放了标定命令。

每次恢复失败都要查明原因。只有在没有无法解释的持续资源增长、陈旧快照发布和 sanitizer 检出的异常时，才验收该次运行。p50/p95/p99 应从记录的样本计算，并附上单位和样本数。

CI 不执行这项长稳测试。FakeTransport 和 vcan 不能证明硬件 ACK、物理 bus-off 行为或设备吞吐量；本流程也不附带已经完成的八小时硬件测试结果。
