# C++ 开发与文档

[English](../CPP_GUIDE.md) · 简体中文 · [文档](README.md)

公共核心库使用 C++17，头文件应能脱离 ROS2 和 Linux 头文件使用；平台代码留在适配器中。新增代码需要通过项目的 `-Wall -Wextra -Wpedantic` 编译检查、格式检查、静态分析和运行测试。

## 公共接口

说明输入、单位、所有权、副作用和失败方式。区分新请求与缓存读取，写清超时从哪里开始、覆盖哪些阶段，以及调用方停止等待后底层操作是否仍可能继续。只有所有路径都满足条件时，才把接口标为 `noexcept`。

公共头文件自行包含依赖，使用限定名称，不使用覆盖整个命名空间的 `using`。协议数据优先使用值类型和定长数组；下标访问和数值窄化前校验长度、范围。线协议解码与传输、ROS 消息转换分开。

## 资源与并发

连接和线程用 RAII 管理，每个资源由明确的一方负责生命周期。共享对象不代表所有调用方都能关闭或恢复它。说明借用对象的生存期和允许并发的调用；先停止调用方，再销毁目标对象。持有状态锁时不要调用用户代码。

区分传输接受、协议回复和设备执行完成。保留错误详情，不用看似有效的零值代替失败。重试策略由具体操作决定，标定不能自动重放。

## 修改与测试

回归测试应调用生产代码，并能捕获它要防止的缺陷。并发测试优先用 FakeTransport 的同步门或可观察状态建立执行顺序，不依赖一次 sleep 恰好制造出竞争。硬件测试须显式选择。

公共行为变化时，在同一 PR 更新两种语言、示例和测试。除了源码树内构建，也要检查安装后的 consumer。静态分析结果与运行验证分别报告：静态报告干净，不代表线程、协议或设备行为已经验证。

已实现的行为见 [API](API.md)、[Session](SESSION.md) 和[测试](TESTING.md)。
